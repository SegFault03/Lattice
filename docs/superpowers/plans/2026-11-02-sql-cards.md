# SQL Cards Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Paint a card behind every SQL region Lattice recognizes (Java/Kotlin injections, each statement in `.sql` files), with a hover toolbar holding Run and Roll Back, Send to Console, Copy SQL and a More menu.

**Architecture:** The new package `com.segfault03.ideadb.sql.card` has three parts:
- **Pure logic:** `SqlCard`, `SqlCardGeometry`, `SqlCardToolbarPlacement`, `SqlCardHoverTimer`.
- **Locator:** `SqlCardLocator`, which reads PSI and injections.
- **IDE glue:** a highlighting pass that owns the card `RangeHighlighter`s, a renderer, a per-editor hover controller that shows an `ActionToolbar` popup, and the toolbar actions.

The existing run actions learn to take their target from a `SQL_CARD` data key and fall back to the caret, so the context menu is unchanged.

**Tech Stack:** Java 21, IntelliJ Platform 2025.1 SDK, JUnit 5 (`src/test`), `BasePlatformTestCase` through JUnit vintage (`src/platformTest`), IDE Starter (`src/uiTest`).

**Spec:** `docs/superpowers/specs/2026-11-02-sql-cards-design.md`

## Global Constraints

- **Fixed copy:**
  - "Show SQL cards" (setting).
  - "Copy SQL" (action text); "SQL copied" (hint).
  - "No connection" (chip).
  - The existing "Select a single statement" and "Bind this file to a connection first".
  - The existing `SqlStatementKind.rollbackRefusal` / `explainRefusal` texts.
- **Ids and keys:** action and group ids are prefixed `com.segfault03.lattice.sql.card.`. The toolbar group is `com.segfault03.lattice.sql.card.toolbar` and its More subgroup is `com.segfault03.lattice.sql.card.more`. The colour key is `LATTICE_SQL_CARD`.
- **Geometry:**
  - Card: 5px horizontal padding, 4px corner radius (arc 8), 1px border.
  - Default colours: light background `#F1F4FC`, border `#DCE3F5`, hover border `#A8B8E6`; dark background `#262A33`, border `#3A4150`, hover border `#5A6B95`.
- **Hover timing:** show 150 ms after the mouse enters a card; hide 300 ms after it leaves both the card and the toolbar. Hide immediately on scroll, typing, focus loss or an invalid highlighter.
- **Where cards appear:** only in `EditorKind.MAIN_EDITOR`, non-viewer editors whose file is not a `SqlConsoleVirtualFile`, and only below the IDE's large-file threshold (`FileUtilRt.isTooLarge`). Never when `SqlEditorSettings.isSqlCardsEffective()` is false or `UltimateDatabasePlugin.isActive()`.
- **Copy SQL** is registered only in the card toolbar group, not in `EditorPopupMenu`.
- **Unchanged behaviour:** the context menu, intentions and caret targeting behave exactly as today. `DryRunActionsFixtureTest` and `SqlRunTargetFixtureTest` must pass unchanged.
- **Fixture test naming:** fixtures that need the Java or Kotlin plugin end in `JavaFixtureTest` / `KotlinFixtureTest` and run with `javaPlatformTest` / `kotlinPlatformTest`. All others run with `platformTest`.
- **Conventions:** follow the surrounding code's density and idiom (`CLAUDE.md`). Docs are current-state.
- **Git:** commit after each task and push `claude/sql-cards` after each task's tests pass (standing approval). Never push another branch.

## Review Focus

- **Edits inside a card:** typing inside an injected string or a statement must keep the card aligned with the text and hide any visible toolbar. After the next pass the highlighter ranges equal the locator's output. Test in Task 4.
- **Soft wrap and folding:** a card over soft-wrapped lines must cover every visual line it spans. A fold collapsed inside a card must not leave the card wider than the visible text. Test in Task 1 (per-visual-line extents) and Task 4 (soft wrap on).
- **Two SQL strings on one line:** `jdbc.query("select 1", "select 2")` gives two cards, and the hover hit-test picks the one under the mouse. Test in Task 3 and Task 7.
- **Kotlin templates:** `"select * from t where id = $id"` gives one card, and Copy SQL yields `select * from t where id = ?`. Test in Task 3 and Task 6.
- **Card near the top edge or wider than the viewport:** the toolbar is never placed off-screen. Test in Task 7.

**Interfaces:**
- Produces:
  - `public record SqlCard(@NotNull List<TextRange> segments, @NotNull String sql, boolean injected, @Nullable SqlStatementKind kind, int statementCount)`.
    - `segments` are host-document ranges, ascending.
    - `kind` is null when `statementCount != 1`.
    - `TextRange range()` spans from the first segment's start to the last segment's end.
  - `SqlCardGeometry`:
    - `record Extent(int x0, int x1, int y, int height)`, one per visual line piece of a segment.
    - `static @NotNull Rectangle bounds(@NotNull List<Extent> extents)`: x from `min(x0) - 5` to `max(x1) + 5`, y from `min(y)` to `max(y + height)`.
    - Constants `PADDING = 5`, `ARC = 8`.
  - `SqlCardToolbarPlacement`:
    - `static @NotNull Point place(@NotNull Rectangle card, @NotNull Dimension toolbar, @NotNull Rectangle visible)`.
    - Default: `x = card.maxX - toolbar.width`, `y = card.y - toolbar.height - 2`.
    - If `y < visible.y`, use `y = card.y + 2` instead.
    - Then clamp x into `[visible.x, visible.maxX - toolbar.width]`.
